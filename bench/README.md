# 読み取り精度の測定

```bash
npm run bench
```

現場写真に近い図面を 5 枚つくり、アプリと同じ読み取りをブラウザの中で動かして、
正解の寸法をいくつ拾えたかを数えます。読み取りの設定を変えたら、これで前後を比べてください。

| 写真 | どんな写真か |
|---|---|
| clean | 白い紙に黒い字。まっすぐ |
| photo | 影・黄ばみ・薄いインク・少しの歪み・手ぶれ・ざらつき |
| far | photo を遠くから撮った(字が小さい) |
| tilt | photo を 4° 傾けた |
| dark | 影が濃く、コントラストが低い |

どの図面にも **縦書きの高さ寸法**(JIS の書き方。下から上へ読む)が 3 つ入っています。

## これまでの結果

同じ 5 枚(乱数の種を固定しているので、何度作っても同じ画像)で比べたもの。

| | 寸法 | 縦書きの高さ |
|---|---|---|
| 最初の版(1600px・そのまま・横だけ読む) | 20/45 (44%) | 0/15 |
| **いまの設定** | **40/45 (89%)** | **12/15** |

いまの設定でやっていること(効いた順):

1. **90°回してもう一度読む** — 縦書きの高さ寸法は、これをしないと 1 つも読めない
2. **影・黄ばみをならす** — 紙の明るさを升目ごとに見積もって割る
3. **写真を 2400px まで残す** — 1600px だと遠くから撮った図面の字が潰れる
4. **頭の欠けた数字を読み直す** — 「,640」は 3,640 の「3」が寸法線にくっついて落ちたもの。
   まわりを 1 行として読み直すと取り戻せる。取り戻せなければ捨てる

試してやめたもの: 読む前に 1.5 倍に拡大 → ほぼ変わらず、時間が 2 倍。

Playwright が必要です(プロジェクトの依存には入れていません)。
`npm i -g playwright && npx playwright install chromium`
